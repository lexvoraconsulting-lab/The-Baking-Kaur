# GitHub Rendering Rules

GitHub is the primary audience surface for this repository's documentation. Visitors read rendered
Markdown on github.com, not in an editor and not in a vault. This reference defines what GitHub
actually renders, so theme work targets techniques that survive instead of techniques that are
silently discarded.

## The Sanitiser Constraint

GitHub passes all inline HTML in Markdown through an allowlist sanitiser before rendering.
Presentational HTML is removed. Repository CSS is never loaded, and there is no way to attach a
stylesheet to a rendered Markdown page.

| S.No. | Technique | Renders on GitHub | Note |
| ---: | --- | --- | --- |
| 1 | `style="..."` attribute | No | Stripped from every element without exception. |
| 2 | `bgcolor`, `color` attributes | No | Not on the allowlist. |
| 3 | `<font color="...">` | No | Element is removed; its text content survives unstyled. |
| 4 | `<span>` with colour intent | No | Offers no styling hook once `style` is gone. |
| 5 | `<style>` block or linked CSS | No | Removed entirely. |
| 6 | `align`, `width` attributes | Yes | Useful for image sizing and column alignment only. |
| 7 | `<details>` / `<summary>` | Yes | Allowed, and the reliable way to fold long sections. |
| 8 | `<picture>` with `prefers-color-scheme` | Yes | The supported light/dark asset switch. |
| 9 | `<img>` with a repository-relative `src` | Yes | Full-fidelity colour, because the file is an image. |

> [!IMPORTANT]
> An HTML table carrying `bgcolor` and `<font>` renders on GitHub as a plain, unstyled table. Do
> not use it as a theming route, and do not describe it as a GitHub-compatible fallback.

## What Colour Is Actually Available

Five routes carry real colour on github.com. Every one of them maps to
[`diagram-color-system.md`](./diagram-color-system.md) semantic roles.

| S.No. | Route | Use for | Theme control |
| ---: | --- | --- | --- |
| 1 | Committed SVG referenced as an image | Banners, architecture diagrams, section headers, any large branded surface. | Total. The SVG is rendered as an image, so every fill, stroke, and font size applies. |
| 2 | Badge SVGs inside plain Markdown tables | Status, severity, and ownership chips in an otherwise normal table. | Total, and the table stays selectable, diffable, and accessible. |
| 3 | Mermaid fenced blocks | Flow, sequence, and architecture diagrams that should stay text-editable. | High, through an `init` directive and `classDef` rules. |
| 4 | GitHub callouts | Priority, risk, prerequisites, and consequences. | Fixed. GitHub owns the five colours; see [`github-callouts.md`](./github-callouts.md). |
| 5 | Syntax-highlighted code fences | Green/red change framing via a `diff` fence; language accents elsewhere. | Fixed, and grammar-driven. |

Do not use the LaTeX `$\color{...}$` hack for prose. It renders as a maths expression, breaks on
spaces and punctuation, is unreadable to screen readers, and inverts badly in dark mode.

## Dark Mode

GitHub renders every page in the visitor's chosen theme. A visual that assumes a light page will
glare or disappear for roughly half the audience.

- Give any large surface a light/dark pair and switch it with `<picture>`.
- Keep small chips self-contained: a badge with its own solid fill and its own border reads
  correctly in both themes, so it needs only one file.
- Never rely on the page background showing through a transparent SVG.

```markdown
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="../assets/banners/lexvora/documentation-dark.svg">
  <img alt="Documentation visual theme" src="../assets/banners/lexvora/documentation-light.svg" width="100%">
</picture>
```

## Mermaid Theme Binding

Bind Mermaid to the selected profile with an `init` directive, then assign semantic roles with
`classDef`. Set the background explicitly so the diagram does not inherit the page theme.

```text
%%{init: {'theme':'base','themeVariables':{
  'background':'#fbf8f3','primaryColor':'#ffffff','primaryTextColor':'#101820',
  'primaryBorderColor':'#b88445','lineColor':'#102d40','fontSize':'14px'}}}%%
```

| S.No. | Semantic role | `classDef` for `lexvora-company` |
| ---: | --- | --- |
| 1 | Governing/root node | `fill:#061421,stroke:#b88445,color:#ffffff` |
| 2 | Architecture/system node | `fill:#102d40,stroke:#b88445,color:#ffffff` |
| 3 | Decision/checkpoint node | `fill:#b88445,stroke:#8a5723,color:#061421` |
| 4 | Documentation node | `fill:#ffffff,stroke:#b88445,color:#101820` |
| 5 | Risk node | `fill:#8a5723,stroke:#061421,color:#ffffff` |

## Badge Chips

Badge SVGs live in [`../assets/badges/<theme>/`](../assets/badges/) and are referenced by relative
path. They are generated by [`../scripts/generate_theme_assets.py`](../scripts/generate_theme_assets.py);
see [`banner-and-badge-system.md`](./banner-and-badge-system.md).
They are the correct answer when a table column needs colour, because the surrounding table stays
plain Markdown.

```markdown
| 1 | Deviation register | ![Resolved](../assets/badges/lexvora/gap-resolved.svg) | Uses the accepted root entry file. |
```

Keep the alt text equal to the label. The colour is decoration; the word carries the meaning, and a
reader with images disabled must lose nothing.

Add a chip by adding one row to `BADGES` in the generator and re-running it, so the chip is created
for every theme profile at once. Never hand-write a file under `assets/badges/`.

## Verification

Before closing any GitHub-targeted theme task:

- View the rendered file on github.com, not only in an editor preview.
- Switch the GitHub appearance setting to dark and re-read the same page.
- Confirm no `style`, `bgcolor`, or `<font>` remains in the source.
- Confirm every image path resolves from the file's own directory.
